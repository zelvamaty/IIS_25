Implementace

Overview

Pro implementaci jsme zvolili framework Django (Python) pro backend a React (JavaScript) pro frontend. Na produkci jsou oba tyto servery skryté za Apache 2, který pracuje jako zpětné proxy, běžíci na tom samém serveru. Celý tento systém je dále chráněn proxy serverem od služby Cloudflare, na kterém je nakonfigurována služba DNS. Komunikace mezi serverama probíhá prostřednictvím protokolu HTTPS, s výjimkou serverů aplikace - ty běží pouze na localhostu, tedy nepovažujeme zde za potřebné šifrování komunikace.

Instalace backendu

1. Konfigurace prostředí:
 1.1. Inicializace virtuálního prostředí (silně doporučeno)
 V terminálu zadejte tyto příkazy: 
cd ~/IIS_25/backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
1.2. Konfigurace běhového prostředí - settings.py (volitelné)
 Pokud zprovozňujete aplikaci pouze na localhostu, nejsou potřebné žádne úpravy tohoto souboru. Pro běh na produkci ale důrazně doporučujeme si vytvořit soubor, ve kterém budou umístěny příslušné přetížení konstant a ten pak použijeme jako soubor nastavení. Další možností je úprava samotného souboru settings.py, ale tuto možnost spíš nedoporučujeme z důvodu možné ztráty předvolených hodnot nastavení.
Soubor pro přetížení předvolených hodnot lze vytvořit nasledujícím způsobem: 
vi ~/IIS_25/backend/backend_iis/backend_iis/local_settings.py
a vložit do něj nasledující obsah: 
from settings import *		# zahrne předvolená nastavení

# Bezpečnostní klíč - nahraďte náhodným ASCII řetězcem o délce alespoň 50 znaků, tento klíč je používán ke zabezpečení podepsaných dat
SECRET_KEY = 'django-insecure-m)c@0!p#gq9x&9*s-g88=8q&z*k^q8$d!q$8y!s#k!a^e(x1@v'

# Debugovací režim - jeho zapnutí na produkci odhaluje citlivé údaje o běhu, silně doporučujeme vypínat pro běh na produkci!
DEBUG = False

# Konfigurace připojení do databáze
DATABASES = {				
    'default': {
        'ENGINE': 'django.db.backends.mysql',	# použitý DBMS (např. pro PostgreSQL použijte 'django.db.backends.postgres')
        'NAME': 'django',                       # název databáze
        'USER': 'django',                       # uživatelské jméno pro přihlášení
        'PASSWORD': 'heslonaGITU',              # uživatelské heslo
        'HOST': 'localhost',                    # doménové jméno nebo IP adresa DBMS
        'PORT': '3306',                         # port, na kterém běží DBMS
    }
}

# Seznam povolených zdrojů požadavků - zde umístíme base URL frontendu.
CORS_ALLOWED_ORIGINS = [
    "http://example.com:3000/"
]
Více v bodě 3b.
2. Inicializace databáze - naplní databázi ukázkovými daty 
python3 manage.py makemigrations
python3 manage.py migrate
python3 manage.py seeder
3a. Spuštění backendu pro vývoj na localhostu: 
python3 manage.py runserver
3b. Spuštění backendu pro běh na produkci:
Jak již bylo v bodě 1.2 zmíněno, předvolené parametry aplikace jsou definovány ve zdrojovém souboru backend_iis/settings.py. Pro aplikaci přetížení těchto parametrů je nutné nastavit proměnnou prostředí DJANGO_SETTINGS_MODULE tak, aby obsahovala celý název modulu, ve kterém se tato přetížení nachází. Toho můžeme docílit např. tímto zbůsobem: 
DJANGO_SETTINGS_MODULE=backend_iis.local_settings daphne --bind <adresa> --port <číslo portu> backend_iis.asgi:application
nebo také tuto proměnnou exportovat: 
export DJANGO_SETTINGS_MODULE=backend_iis.local_settings 
daphne --bind <adresa> --port <číslo portu> backend_iis.asgi:application
Poznámka: Program daphne je standalone server, nejedná se o nástroj pro řízení běhu (jako např. systemctl) - je tedy možné ho spouštět např. jako systémovou službu pod systemd.

Instalace frontendu

1. Inicializace prostředí 
cd ~/IIS_25/frontend
npm install
2a. Spuštění frontendu pro vývoj: 
npm start
2b. Spuštění frontendu pro běh na produkci:
 Před nasazením do produkce je nutné změnit základní URL pro volání backendu. Toho docílíme vytvořením souboru .env v adresáři ~/IIS_25/frontend, do kterého vložíme následující řádek (bez <>): 
REACT_APP_API_BASE_URL=<base_URL>
Poté je možné aplikaci sestavit pro běh v produkci a spustit standardním způsobem: 
npm run build
serve -s build
